### Exact cause and narrow repair

The dependency's [`parseValue()`](../node_modules/prismarine-schematic/lib/states.js:11) converted integer property strings directly into numeric offsets. Minecraft's state IDs instead use each value's zero-based position in the registry's ordered value list. Thus one-based candle counts, leaf distances and snow layers were encoded one step too high. At a block's maximum value, this can overflow into the next block's state range: oak distance-7 leaves became spruce leaves, spruce became birch, flowering azalea became wet sponge; a synthetic maximum-layer snow fixture became ice. This is not invalid Sponge NBT, bad blueprint geometry, a VarInt problem, a registry-version mismatch, or a validator normalization error. The existing Minecraft-data protocol and builder cancellation patches are unrelated.

The new [version-pinned dependency patch](../patches/prismarine-schematic+1.3.0.patch) uses the declared integer value's index when an explicit value list exists. Existing enum/boolean behavior, numeric fallback when no list exists, omitted-property interpretation and file-format parsing remain unchanged. It fixes both the [`readSchematic()` wrapper](../src/utils/schematic/reader.js:173) and the build entry point's [direct dependency-reader path](../src/utils/schematic/build_schematic.js:132), including legacy names routed through the same encoder. The existing postinstall patch mechanism applies it; reapply dependency patches in existing installations before using these artifacts. No compiler, validator, application source, dependency version, blueprint or canonical schematic was changed to obtain a pass.

### Actual bot impact and remaining limits

This affected actual placement planning, not just validation. The [adapter](../src/utils/schematic/modern_build.js:140) derives block names, item selection, action properties and the verification plan from decoded IDs. Consequently, corrupted foliage selected the wrong inventory item, and the [final world verifier](../src/utils/schematic/build_schematic.js:52) checked the wrong target states. The [diagnostic log](validation/reader_diagnosis.log) demonstrates those wrong item/plan choices. The repair restores the intended species, state IDs and properties in the plan; it does not add new placement capabilities or weaken verification.

The existing builder still performs ordinary item placement with limited orientation handling, not arbitrary state setting. Multi-candle counts, multi-layer snow, lit states, foliage distance, neighbor-dependent states and other properties may require interactions or may change under server physics. Correct reader output does not guarantee the bot can reproduce every state in-world. No live-server placement, support/physics, redstone/functionality or exact visual-fidelity test was performed. All original reconstruction, dry-fluid, entity/NBT and occluded-geometry limitations remain in force; PARTIAL reconstruction statuses are not promoted to DONE.
